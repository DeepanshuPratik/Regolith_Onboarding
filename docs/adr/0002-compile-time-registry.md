# Compile-time platform registry, not runtime plugins

The mapping from session to service implementations is a **compile-time registry**: an ordered list of `Platform` classes baked into the binary, walked per capability. Runtime `.so` plugins were rejected because they mean owning a public GObject ABI across Vala compiler versions, for a set of desktops that changes about once a year. A config-declared platform — a `platform.conf` naming shell commands per capability, for a desktop nobody wants to write Vala for — layers on top of this without reshaping it: it is one more `Platform` in the list whose `claims_session()` reads a file instead of an environment variable. The trade-off is that adding a desktop is a one-line change plus a rebuild, not a drop-in file a distro can ship post-release; the win is that the binary is self-contained and its capabilities are fixed and knowable.
